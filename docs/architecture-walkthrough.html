مرجع فني: كل ملف بيعمل إيه، مين بينادي مين، النوع اللي بيرجع، والكاستينج. مكتوب للكود بعد الـ P0 pass.

0) الصورة الكبيرة

Clean Architecture + Feature-first. الاتجاه: Presentation → Domain → Data. الـ Presentation ميعرفش Supabase، والـ Domain ميعرفش مين بينفذ، والـ Data هو الوحيد اللي بيتكلم مع السيرفر.

قاعدة 1: Either<Failure, T>

res.fold(
  (failure) => ... , // Left
  (data)    => ... , // Right
);

معناها: دالة واحدة بتتنفذ، حسب الحالة. كل repository بيرجع Either، ومفيش exception بيطلع برّه الـ data layer.

قاعدة 2: States sealed + Equatable

sealed بتخلي الـ switch إجباري يغطي كل الحالات. Equatable بتخلي البلوك ميبعتش state مساوية للقديمة.

جدول GoRouterState

الخاصيةالنوعالمعنى بدقةمثال على /signup?email=a@b.com
state.uriUriالعنوان الكامل مع query/signup?email=a@b.com
state.matchedLocationStringالمسار الذي تمت مطابقته، بدون query ولا fragment/signup
state.fullPathString?نمط الراوت كما هو معرّف (بالـ :params)/signup
state.pathParametersMap<String,String>قيم :id من النمط{}
state.queryParametersMap<String,String>قيم بعد علامة ؟{email: a@b.com}
state.extraObject?كائن عشوائي يُمرر مع go(extra:) ولا يبقى بعد إعادة التشغيل—
state.nameString?اسم الراوتsignup

دلالات redirect بدقة

  • التوقيع: FutureOr<String?> Function(BuildContext, GoRouterState).
  • بيتنفذ: عند البداية، عند كل go/push، وعند كل notify من refreshListenable.
  • null = اسمح/خليك مكانك. String أو Uri = انتقل لهناك (وتعاد دورة redirect على الهدف).
  • لو رجّعت نفس المكان: GoRouter بيعتبرها لا تغيير لمنع الحلقة.
  • الـ state اللي بتوصلك هي الهدف مش الشاشة الحالية.
  • الترتيب: redirect العام أولاً، ثم redirect الخاص بالراوت.
خطأ شائع: المقارنة بـ state.uri.toString() بدل matchedLocation — الـ query بيلخبط المقارنة وتدخل حلقة redirect.

11) أسئلة وأجوبة (مرجع سريع)

initState vs didChangeDependencies

initStatedidChangeDependencies
عدد المراتمرة واحدةمرة بعد initState + كل مرة تتغير فيها dependency
InheritedWidgetممنوعمسموح
الاستخدامControllers / FocusNode / أول eventTheme.of / MediaQuery / GoRouterState / context.locale

ليه لا نستخدم rethrow وخلاص

rethrow في catch فاضي = كود ميت. الـ datasource بيرمي exceptions الأصلية من Supabase، والـ repository بيترجمها. بنرمي exception بنفسنا فقط لما الخطأ يكون من عندنا (مفيش صف users، مفيش session) — والأفضل تعريف exception خاص بيه بدل استخدام AuthException.

تكرار توست جوجل

الـ initState بيشتغل عند الظهور، والـ BlocListener بيشتغل عند التغيّر فقط. دخول من deep link: الحالة اتغيرت قبل ما الشاشة تظهر → initState بس. تغيّر تاني والشاشة ظاهرة → listener بس. الحل الأنضف: listener واحد على مستوى الجذر داخل MaterialApp.router.builder.

RLS مش بتحمي القيم

الـ policy بتحدد أي صفوف تقدر تلمسها، مش القيم اللي بتبعتها. فمستخدم معدّل يقدر يبعت xp=9999 وهو بيعمل insert لصفه. الحل: defaults + trigger + منع الكتابة، والـ XP/Coins تتحدّث فقط من دوال SECURITY DEFINER.
